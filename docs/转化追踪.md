# 转化追踪

本文档记录 Kastave V2 独立站当前的转化追踪、支付记录和上线核对方式。

## 当前目标

核心转化路径：

1. 用户进入首页。
2. 用户留下邮箱，或点击 `Reserve for $1`。
3. 用户进入 `/deposit`。
4. 用户选择 Stripe 信用卡或 PayPal 支付 `$1` founder reservation。
5. 支付平台发送回执；Vercel webhook 记录有效付款事件。

首页 CTA 不直接跳转 Stripe 或 PayPal。当前产品目标是先让用户理解 `$1` 预订权益，再选择支付方式。

## 前端事件

前端入口在 `src/tracking.js`，页面动作在 `src/App.jsx` 中触发。

主要事件：

- `page_view`：页面访问，对应 Meta `PageView`。
- `view_content`：用户看到主要 section，对应 Meta `ViewContent`。
- `lead_intent`：用户开始填写邮箱，对应 Meta `LeadIntent`。
- `lead`：用户提交邮箱，对应 Meta `Lead`。
- `signup_continue_to_deposit`：邮箱提交后进入 `/deposit`。
- `deposit_page_open`：进入支付页或点击预订 CTA。
- `deposit_checkout_jump`：支付页 hero 按钮滚动到支付方式区域。
- `initiate_checkout`：用户点击 Stripe 或 PayPal，对应 Meta `InitiateCheckout`。
- `outbound_click`：打开外部支付链接。
- `payment_failed`：支付链接缺失或跳转失败。
- `page_engagement`：离开页面时记录停留时长。

所有事件都会先构造成统一 payload，包含路径、URL、标题、referrer、设备类型、UTM、click id 和 `event_id`。

## Meta Pixel

默认 Pixel ID：

```text
1542765323857764
```

代码位置：

- `src/tracking.js`：运行时加载 `https://connect.facebook.net/en_US/fbevents.js` 并调用 `fbq("init", metaPixelId)`。
- `index.html`：包含 `<noscript>` 图片兜底。

环境变量：

```text
VITE_META_PIXEL_ID=1542765323857764
```

如需更换 Pixel，只修改环境变量和 `index.html` noscript ID，确保测试同步更新。

## Meta 高级匹配

当前前端代码不主动向 Meta 发送邮箱、电话、姓名、生日、城市、邮编等个人身份字段。

建议口径：

- 可以保留 Meta 后台的自动高级匹配能力，用于 Meta 自己从表单字段中识别匹配信号。
- 不要在代码里手动调用 `fbq("init", pixelId, { em, ph, fn, ln })`。
- 不要把明文邮箱、电话、姓名或地址写进 `trackEvent` payload。
- 如果未来要接 Meta CAPI 或手动高级匹配，必须先增加隐私说明、同意机制、字段 hash 处理和测试用例。

当前站点的 Meta 事件只发送行为和页面上下文：`PageView`、`ViewContent`、`LeadIntent`、`Lead`、`InitiateCheckout`、`Purchase`、自定义点击和停留事件。

注意：`/thanks` 页面触发的 Meta `Purchase` 用于广告平台归因和回访信号，不作为内部真实付款确认。内部付款确认以 Stripe / PayPal webhook 写入的 `purchase_events` 为准。

## Supabase

前端匿名写入依赖：

```text
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```

前端写入表：

- `landing_events`：页面、CTA、FAQ、支付点击等行为事件。
- `waitlist_signups`：邮箱。
- `reservation_intents`：用户点击 Stripe / PayPal 的预订意图，不等于付款完成。

后端 webhook 写入依赖：

```text
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

后端写入表：

- `purchase_events`：Stripe / PayPal webhook 已验证的 `$1` 支付完成事件。浏览器前端不写这个表。
- `landing_events`：支付失败、退款、拒付等支付平台事件。

初始化 SQL 按顺序执行：

1. `supabase/migrations/202605140001_landing_metrics.sql`
2. `supabase/migrations/202605160001_landing_metric_rates.sql`
3. `supabase/migrations/202605160002_pretest_tracking_summary.sql`

## Stripe

前端支付链接：

```text
VITE_STRIPE_PAYMENT_LINK=https://buy.stripe.com/9B69AVbpieTIcPx9rBd7q00
```

Webhook endpoint：

```text
https://kastave.com/api/stripe-webhook
```

订阅事件：

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`
- `checkout.session.async_payment_failed`

后端环境变量：

```text
STRIPE_WEBHOOK_SECRET=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```


Webhook endpoint：

## 上线前检查

本地必须通过：

```bash
npm run preflight
```

页面检查：

1. 首页 `Sign up` 提交邮箱后进入 `/deposit`。
2. 首页 `Reserve for $1` 进入 `/deposit`。
3. `/deposit` 展示 Stripe 和 PayPal 两种支付方式。
4. 点击 Stripe / PayPal 只验证打开对应支付页，不输入真实卡号，不完成真实交易。
5. `/privacy`、`/terms`、`/policies/privacy-policy`、`/policies/terms-of-service` 可访问。
6. Meta Events Manager 能看到 `PageView`、`ViewContent`、`Lead`、`InitiateCheckout` 测试事件。
7. Stripe / PayPal 后台 webhook 测试事件返回 2xx。

生产环境变量必须通过：

```bash
npm run deploy:ready
```

`deploy:ready` 会先跑完整本地门禁，再检查生产环境变量和支付链接 smoke test。没有真实 Vercel production secret 的本地 shell 失败是预期结果；上线前需要在 Vercel production 环境中配置完整变量后再通过。

支付链接可单独检查：

```bash
npm run check:payment-links
```

这个命令只验证公开 payment link 是否可打开、是否返回商户错误页，不会完成真实付款。

生产后台核对：

1. Stripe Payment Link redirect：`https://kastave.com/thanks?provider=stripe`。
2. Stripe webhook endpoint：`https://kastave.com/api/stripe-webhook`。
3. PayPal return URL：`https://kastave.com/thanks?provider=paypal`，如果当前 PayPal payment link 支持。
4. PayPal webhook endpoint：`https://kastave.com/api/paypal-webhook`。
5. Supabase `purchase_events` 只接受 webhook 写入，不用浏览器前端写入。

## 判断口径

- `reservation_intents` 代表用户点击支付渠道，不代表已付款。
- `purchase_events` 代表 webhook 验证后的付款完成记录，只应由 Vercel serverless webhook 写入。
- `landing_events.event_name = 'purchase'` 代表用户到达 `/thanks` 后的前端归因事件，不等于 webhook 验证付款。
- Stripe / PayPal 回执是用户侧第一确认。
- Supabase 记录是内部运营核对依据。
- 不在前端保存 card number、PayPal 登录信息、token、cookie、secret 或 service role key。
