# 仓库重命名接口设计

## 目标

设计一个安全、可预览、可审计的仓库重命名接口，用于把当前 GitHub 仓库名调整为更清晰的英文 slug，同时保留中文项目名作为 README 和文档中的展示名称。

该接口不直接暴露 GitHub 底层能力给前端，而是先经过业务层校验、预览和确认，再映射到 GitHub 官方仓库更新接口。

## 设计原则

- 先预览，后执行。
- 默认不改可见性、不改默认分支、不删除文件。
- 必须校验用户是否拥有仓库 admin 权限。
- 必须校验新仓库名是否符合 GitHub slug 规则。
- 必须生成重命名后检查清单。
- 必须记录审计日志。
- 执行失败时返回明确错误码，不做静默重试。

## 接口总览

```text
POST /api/github/repositories/rename/preview
POST /api/github/repositories/rename
GET  /api/github/repositories/rename/jobs/{job_id}
POST /api/github/repositories/rename/rollback-preview
```

## 1. 预览接口

```http
POST /api/github/repositories/rename/preview
Content-Type: application/json
```

## 2. 执行接口

### 请求

```http
POST /api/github/repositories/rename
Content-Type: application/json
```

```json
{
  "owner": "Chesterzero000",
  "current_name": "ai-",
  "target_name": "kastave-bank-angler-landing",
  "display_name_zh": "Kastave 岸钓侦察员落地页",
  "confirm": true,
  "expected_current_full_name": "Chesterzero000/ai-",
  "update_readme": false
}
```

### 响应

```json
{
  "ok": true,
  "job_id": "repo_rename_20260525_001",
  "status": "completed",
  "old_full_name": "Chesterzero000/ai-",
  "new_full_name": "Chesterzero000/kastave-bank-angler-landing",

}
```

## 4. 回滚预览接口

GitHub 仓库重命名没有真正的事务回滚。回滚本质上是再次把仓库名改回旧名称，所以必须先检查旧名称是否仍可用。

```http
POST /api/github/repositories/rename/rollback-preview
Content-Type: application/json
```

```json
{
  "owner": "Chesterzero000",
  "current_name": "kastave-bank-angler-landing",
  "rollback_name": "ai-"
}
```

## 错误码

| 错误码 | HTTP | 含义 |
| --- | --- | --- |
| `REPO_NOT_FOUND` | 404 | 当前仓库不存在或无权限访问 |
| `NO_ADMIN_PERMISSION` | 403 | 当前用户没有 admin 权限，不能重命名 |
| `INVALID_TARGET_NAME` | 400 | 新仓库名不符合 slug 规则 |
| `TARGET_NAME_TAKEN` | 409 | 目标仓库名已被占用 |
| `CONFIRM_REQUIRED` | 400 | 执行接口缺少 `confirm: true` |
| `EXPECTED_REPO_MISMATCH` | 409 | 当前仓库名与预期不一致，避免误操作 |
| `GITHUB_API_FAILED` | 502 | GitHub 更新仓库接口失败 |
| `POST_VERIFY_FAILED` | 500 | 执行后无法验证新仓库状态 |

## 参数校验

`target_name` 建议规则：

```text
^[a-z0-9][a-z0-9-]{1,98}[a-z0-9]$
```

约束：

- 使用小写英文、数字和连字符。
- 不以连字符开头或结尾。
- 不使用中文、空格、下划线和特殊符号。
- 不超过 100 个字符。
- 不使用含义模糊的名称，例如 `ai-`、`test`、`new`、`repo`。

## 执行层映射

业务层通过校验后，执行层可映射到 GitHub REST API：

```http
PATCH https://api.github.com/repos/{owner}/{repo}
Authorization: Bearer <token>
Accept: application/vnd.github+json
Content-Type: application/json
```

```json
{
  "name": "kastave-bank-angler-landing"
}
```

## 前端交互建议

重命名弹窗包含：

- 当前仓库名，只读。
- 中文项目名，可编辑。
- 建议英文 slug，可编辑。
- 影响预览区域。
- 必填确认框：`我确认要重命名仓库，并会更新部署和本地 remote。`
- 主按钮：`预览影响`。
- 二次确认按钮：`确认重命名`。

## 安全注意事项

- 不允许批量重命名直接执行；批量模式只能逐个预览、逐个确认。
- 不允许同时修改仓库可见性。
- 不允许自动删除旧本地目录。
- 不在日志中记录 token。
- 私有仓库的名称和 URL 在报告中按用户授权范围展示。
