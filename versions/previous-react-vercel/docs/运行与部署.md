## 上线前检查

```bash
npm run preflight
```

如果当前环境没有 `npm` / `npx`：

```bash
/Users/chester/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/preflight.mjs
```

`preflight` 会执行：

1. `src/` 和 `api/` 下的 Node 测试。
2. 项目结构检查，确认只保留当前 V2 独立站交付物和项目内 skills。
3. 素材引用检查，确认 V2 图片和公开素材存在，且旧 PNG / GitHub Pages 资产没有被源码重新引用。
4. 部署目标检查，确认 Vercel rewrite、Stripe/PayPal webhook、`.env.example` 和无 GitHub Pages 残留。
5. React 渲染 smoke test，覆盖首页 CTA、deposit 支付按钮、thanks、legal 页面、未知路由 fallback、内部锚点、内部路由和外部支付链接白名单。
6. Vite 生产构建。
7. `dist/404.html` 与 `dist/index.html` 的 SPA fallback 一致性检查。
8. Vite production preview 路由 smoke test，覆盖首页、deposit、thanks、legal/policy aliases 和未知路由 fallback。
9. 常见 live secret / token / private key 扫描。

`preflight` 只验证当前代码是否适合本地验收，不要求真实生产密钥。准备正式部署时，使用更严格的上线门禁：

```bash
npm run deploy:ready
```

如果当前环境没有 `npm` / `npx`：

```bash
/Users/chester/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/deploy-ready.mjs
```

`deploy:ready` 会先执行完整 `preflight`，再执行生产环境变量检查；只有生产 Stripe、PayPal、Supabase 和 Meta Pixel 变量齐全且格式合理时才通过。

`deploy:ready` 还会执行支付链接 smoke check，确认 Stripe / PayPal 链接能打开，并且没有返回常见商户错误页。`preflight` 失败时会立即停止；生产 env 和支付链接会尽量都跑完并汇总阻断项，避免只看到第一个失败原因。

`deploy:ready`、`check:prod-env` 和 `check:payment-links` 会自动读取本地私有文件 `.env.production.local`。这个文件被 `.gitignore` 忽略，适合临时放真实生产变量做上线前验证；不要提交到 GitHub。也可以显式指定文件：

```bash
npm run deploy:ready -- --kastave-env-file .env.production.local
```

如果需要在本地镜像 Vercel production 环境变量，可以先跑清单脚本。它只读取本机 shell 和被忽略的 `.env.production.local`，不读取 Vercel 后台；它只显示变量是否已配置或格式是否合理，不打印密钥值：

## 支付链接检查

```bash
npm run check:payment-links
```

如果当前环境没有 `npm` / `npx`：

```bash
/Users/chester/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node scripts/check-payment-links.mjs
```

这个检查只访问公开 Stripe / PayPal payment link，不输入付款信息、不登录、不完成付款。它会拦截以下风险：

- payment link 不是 HTTPS。
- payment link host 不是预期的 Stripe / PayPal。
- payment link 返回非 2xx。
- payment link 页面包含 `Something went wrong`、`Contact the merchant` 等常见商户配置错误。

当前仓库使用浏览器验证过的 PayPal `$1` payment link：`https://www.paypal.com/ncp/payment/6W9PTBNB267ZW`。如果 PayPal 后台重新生成链接，先更新 `VITE_PAYPAL_PAYMENT_LINK`，再做支付链接检查。

更新 PayPal 链接后，先把新链接写入 `.env.production.local` 的 `VITE_PAYPAL_PAYMENT_LINK`，再运行：

```bash
npm run check:payment-links -- --kastave-env-file .env.production.local
```

### Production 变量来源

| 变量 | 必填 | 来源 | 用途 |
| --- | --- | --- | --- |
| `VITE_STRIPE_PAYMENT_LINK` | 是 | Stripe Payment Link | `/deposit` 的信用卡支付入口 |
| `STRIPE_WEBHOOK_SECRET` | 是 | Stripe webhook endpoint signing secret，通常以 `whsec_` 开头 | 验证 Stripe webhook 签名 |
| `VITE_PAYPAL_PAYMENT_LINK` | 是 | PayPal payment link | `/deposit` 的 PayPal 支付入口 |
| `PAYPAL_CLIENT_ID` | 是 | PayPal developer app | 验证 PayPal webhook 签名 |
| `PAYPAL_CLIENT_SECRET` | 是 | PayPal developer app | 验证 PayPal webhook 签名 |
| `PAYPAL_WEBHOOK_ID` | 是 | PayPal webhook 配置页 | 验证 PayPal webhook 签名 |
| `PAYPAL_ENV` | 是 | `live` 或 `sandbox` | 决定 PayPal API 环境 |
| `SUPABASE_URL` | 是 | Supabase project settings | webhook 后端写入付款记录 |
| `SUPABASE_SERVICE_ROLE_KEY` | 是 | Supabase service role key | webhook 后端写入付款记录 |
| `VITE_META_PIXEL_ID` | 是 | Meta Events Manager | 广告像素追踪 |
| `VITE_SUPABASE_URL` | 建议 | Supabase project settings | 前端匿名事件、邮箱和预订意图 |
| `VITE_SUPABASE_ANON_KEY` | 建议 | Supabase anon public key | 前端匿名事件、邮箱和预订意图 |
| `RESEND_API_KEY` | 建议 | Resend API key | 用户提交邮箱后，给内部团队发送邮件通知 |
| `LEAD_NOTIFY_TO` | 建议 | 你的接收邮箱 | 新邮箱线索通知收件人 |
| `LEAD_NOTIFY_FROM` | 建议 | Resend 已验证发件地址 | 新邮箱线索通知发件人 |
| `VITE_PLAUSIBLE_DOMAIN` | 建议 | Plausible domain | 轻量访问分析 |
| `VITE_BEEHIIV_FORM_URL` | 建议 | Beehiiv embed/form URL | 备用 newsletter 跳转 |

不要把 `STRIPE_WEBHOOK_SECRET`、`PAYPAL_CLIENT_SECRET`、`SUPABASE_SERVICE_ROLE_KEY` 或 `RESEND_API_KEY` 写进前端代码、文档正文真实值、Git commit 或浏览器环境。它们只能放在 Vercel production environment variables。

### 邮箱线索通知

用户提交邮箱后，前端会继续写入 Supabase 的 `waitlist_signups`，同时调用 `/api/lead-notification`。该接口使用 Resend 给 `LEAD_NOTIFY_TO` 发送通知邮件。

需要在 Vercel Production 环境变量中配置：

```text
RESEND_API_KEY=
LEAD_NOTIFY_TO=你的接收邮箱
LEAD_NOTIFY_FROM=Kastave <你的 Resend 已验证发件地址>
```

如果这三个变量未配置，接口会返回非阻塞状态，用户提交邮箱不会失败，但你不会收到邮件通知。

## 部署选择

如果需要 Stripe / PayPal webhook，主部署应使用 Vercel，因为 `api/` 目录依赖 Vercel serverless functions。GitHub Pages 只能部署静态页面，不能处理 `/api/stripe-webhook` 或 `/api/paypal-webhook`。

## Vercel 部署

Vercel 输出目录设置为：

```text
dist
```

需要在 Vercel 环境变量里配置 `.env.example` 中列出的变量。

部署前必须满足：

1. 本地 `npm run preflight` 通过。
2. 页面视觉和支付路径经过人工确认。
3. Vercel production 环境变量配置完成，并且 `npm run deploy:ready` 通过。
4. GitHub push 和 Vercel 部署完成后，`npm run check:release-state` 通过。
5. Stripe Payment Link 和 PayPal return URL 指向 `https://kastave.com/thanks`。
6. Stripe / PayPal production webhook 指向 `https://kastave.com/api/stripe-webhook` 和 `https://kastave.com/api/paypal-webhook`。

### 支付后台设置

Stripe：

1. Payment Link 金额为 `$1.00 USD`，产品名建议为 `Kastave Founder Reservation`。
2. Payment Link completion redirect 设置为 `https://kastave.com/thanks?provider=stripe`。
3. Webhook endpoint 设置为 `https://kastave.com/api/stripe-webhook`。
4. Webhook events 至少订阅 `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.async_payment_failed`。
5. 把 endpoint signing secret 填入 Vercel 的 `STRIPE_WEBHOOK_SECRET`。

PayPal：

1. Payment Link 金额为 `$1.00 USD`，标题建议为 `Kastave Founder Reservation`。
2. 如果 PayPal 当前 payment link 支持 return URL，设置为 `https://kastave.com/thanks?provider=paypal`。
3. Webhook endpoint 设置为 `https://kastave.com/api/paypal-webhook`。
4. Webhook events 至少订阅 `PAYMENT.CAPTURE.COMPLETED`、`PAYMENT.CAPTURE.DENIED`、`PAYMENT.CAPTURE.REFUNDED`、`PAYMENT.CAPTURE.REVERSED`。
5. 把 PayPal app credentials 和 webhook ID 填入 Vercel 的 `PAYPAL_CLIENT_ID`、`PAYPAL_CLIENT_SECRET`、`PAYPAL_WEBHOOK_ID`、`PAYPAL_ENV=live`。

## 当前预订路径

V2 首页的预订路径是：

1. 首页 `Sign up` 收集邮箱后进入 `/deposit`。
2. 首页 `Reserve for $1` 进入 `/deposit`。
3. `/deposit` 展示 `$1` founder reservation、`$100` launch credit、Stripe 信用卡和 PayPal 两种支付方式。
4. Stripe / PayPal 付款完成后依赖支付平台回执和 webhook 记录完成支付。

除非是明确的临时热修复，不要把首页 CTA 改回直接跳 Stripe 或 PayPal。

## 关键注意事项

- PayPal 点击不是支付完成确认，完成支付需要 PayPal 后台或 webhook。
- Stripe 点击也不是支付完成确认，完成支付需要 Stripe 后台或 webhook。
- 生产环境不要提交 `.env.local`。
- 广告像素、分析工具和 Supabase key 应通过平台环境变量配置。
